# 状态升级与保留

[文档索引](../../README.md) · [English](../en/state-evolution.md)

Turnyard 已支持停止 supervisor 后备份、校验、恢复和逐个清理终态会话。SQLite 结构升级现使用版本化迁移；自动保留期限和磁盘硬配额仍是后续工作。

## 数据库升级

`internal/store/migrations/001_baseline.sql` 固定当前 Ent 结构。`OpenStore` 不再调用 Ent 自动建表；启动时读取数据库迁移版本及 SQL 文件校验和，只按顺序应用仓库中的迁移。新数据库直接建表；已知的无版本旧库先用 SQLite `VACUUM INTO` 生成备份并运行完整性检查，然后在事务中补齐旧版追加字段、导入旧 `task_repositories` 基准记录并登记版本。遇到未知结构、新于程序的版本、修改过的迁移或校验失败，启动会报错。已有版本库的后续升级也先备份，再在事务中应用 SQL 与记录版本。

supervisor 持有状态目录独占锁后才打开数据库。迁移失败时保留原库与备份；回退应离线恢复整份备份到新目录，不假定反向 SQL 能恢复数据。数据库版本与输入 JSON 的 `schemaVersion` 独立。每次后续结构变更须增加编号 SQL、旧版本夹具和升级测试，不修改已发布迁移文件。

当前测试覆盖新库、无版本旧库基准记录、重复打开、未知或修改版本、失败回滚，以及 Ent 结构与迁移基线一致性。真实大型旧库及未来第二版迁移仍须在发布前单独演练。

## 数据保留与容量

保留策略由执行机管理员配置，不允许任务输入自行缩短期限。首版只生成清理候选清单和总字节报告；确认策略稳定后才加入定时清理。仅 `completed`、`cancelled` 会话可成为候选；`running`、`paused`、`unknown` 及其受管子会话不能自动删除。父会话在子会话清理完之前不能清理。

每次清理仍沿用现有的独占锁、完整备份、摘要校验和逐会话 `prune` 语义。清理记录应保存会话 ID、终态时间、备份位置、字节数和结果，但不能把备份当作在线热数据无限复制。为日志、检查点和附件分别统计体积；磁盘紧张时拒绝新任务并明确返回容量错误，保留审阅和恢复能力。当前实现只有用量告警，没有磁盘硬配额或自动清理。

验收：活动或未知任务始终被排除；备份内容变化阻止删除；符号链接不能把清理范围扩出状态目录；失败后可从备份恢复并重新读到原产出清单；达到磁盘阈值时不会删除未经备份的数据。
