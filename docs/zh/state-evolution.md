# 状态升级与保留方案

[文档索引](../../README.md) · [English](../en/state-evolution.md)

本文是后续实现方案。现有命令已经支持停止 supervisor 后备份、校验、恢复以及逐个清理终态会话；自动期限和版本化数据库迁移尚未实现。

## 数据库升级

1. 以当前 Ent Schema 建立版本化迁移基线；每次结构变更提交独立迁移文件、校验和与旧库夹具。停止在 `OpenStore` 中对正式数据库直接执行未审查的结构升级。
2. supervisor 启动时先检查数据库版本。新程序只能打开已知的旧版本并按顺序升级；遇到比程序新的版本或缺失迁移时拒绝启动。每步迁移和版本登记在同一 SQLite 事务中完成。
3. 升级前取得状态目录独占锁，生成并验证完整备份；迁移失败时保留原备份和错误，不能自动删除。回退以恢复整份备份到新目录为准，不承诺反向 SQL 能恢复数据。
4. 对已发布输入 JSON 的 `schemaVersion` 单独维护兼容窗口。数据库版本与外部输入版本不共用编号。

验收：真实旧库副本能升级并保留会话、候选和检查点；重复启动无重复迁移；中途注入失败后旧库及备份可恢复；新数据库被旧程序拒绝；迁移期间第二个 supervisor 无法同时打开状态目录。

## 数据保留与容量

保留策略由执行机管理员配置，不允许任务输入自行缩短期限。首版只生成清理候选清单和总字节报告；确认策略稳定后才加入定时清理。仅 `completed`、`cancelled` 会话可成为候选；`running`、`paused`、`unknown` 及其受管子会话不能自动删除。父会话在子会话清理完之前不能清理。

每次清理仍沿用现有的独占锁、完整备份、摘要校验和逐会话 `prune` 语义。清理记录应保存会话 ID、终态时间、备份位置、字节数和结果，但不能把备份当作在线热数据无限复制。为日志、检查点和附件分别统计体积；磁盘紧张时拒绝新任务并明确返回容量错误，保留审阅和恢复能力。当前实现只有用量告警，没有磁盘硬配额或自动清理。

验收：活动或未知任务始终被排除；备份内容变化阻止删除；符号链接不能把清理范围扩出状态目录；失败后可从备份恢复并重新读到原产出清单；达到磁盘阈值时不会删除未经备份的数据。
